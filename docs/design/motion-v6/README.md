# V6 游动与步态

背景与鱼种素材不变，只改动画和运动。所有截图都由实际渲染器在 240×320 画布上生成，3×/4× 图是最近邻放大，不是效果图。

## 改了什么

- **避让**：按 34×20 的椭圆鱼身计算距离，并且优先从上方或下方让开；被邻居推开不会触发掉头。
- **前后两层**：后层鱼按“远处水色”压暗并先绘制，前层鱼后绘制；换层只在掉头的窄帧里发生，看不出亮度跳变。
- **掉头**：0.36 秒内依次显示“略窄（50%）→ 很窄（22%）→ 翻面 → 很窄 → 略窄”，转身时减速，不会高速倒游；两次掉头至少间隔 1.2 秒（追食除外）。
- **摆尾**：4 帧，从尾根到尾尖的行进波，加上尾鳍侧摆时的轻微缩短；头和身体像素不变。摆动频率随游速变化（0.7–3 Hz），停着时只慢慢晃。
- **上下游动**：上下速度最多为巡游速度的 45%；爬升或下潜时身体按列错位最多约 2 像素，表现抬头或低头。
- **螃蟹**：始终横着走、不镜像；腿分两组交替抬起，帧数按走过的距离（每 3 像素一帧）切换，站着时脚不动；每走 12 像素会顿一下，吃到食物停 0.8 秒。
- **夜晚**：鱼、螃蟹、藻点、气泡、鱼食都按夜间色调压暗，和夜景背景一致。

## 实测（5 分钟确定性模拟，含两次喂食）

| 指标 | V5 | V6 |
|---|---|---|
| 同层两鱼鱼身重叠时间占比 | 10.4% | 1.1% |
| 同层两鱼中心距离 < 20 像素占比 | 8.5% | 1.0% |
| 上下速度 / 左右速度 | 0.77 | 0.33 |
| 掉头时有过渡帧 | 否 | 是 |

## 资源

- 帧都只存朝右的一份；设备上画图时反向读取列即可镜像，按列加 y 偏移就是抬头或低头，按通道乘加就是明暗。这些都是逐像素绘制操作，不需要运行时缩放。规则写在 `prototype/assets/manifest.json` 的 `sprites.runtime`。
- 124 帧，`fish.rgb565a8` 为 1,137,012 字节（V5 为 144 帧、1,450,476 字节）；位图合计 1,447,263 字节。
- 夜景背景约 2% 的字节相差 1 个最低位，原因是画布改为 CPU 回读后半透明叠色的取整方式变了。

## 文件

`day-60s-3x.png`、`night-60s-3x.png`：开局 60 秒的白天和夜晚。`turn-strip-4x.png`：一次掉头的连续 8 帧。`motion-frames-3x.png`：成鱼尺寸的全部帧（摆尾 0–3、掉头宽/窄；螃蟹步态 0–3）。`aquadays-live-v6.gif`：8 秒实际画面，含一次喂食。其余为四个状态截图和画板。

## 尚存限制

- 夜晚螃蟹在深色石头前对比度低。
- 掉头是水平压窄，不是真的三维转身；22% 窄帧看起来是鱼正对或背对镜头。
- 幼鱼长成成鱼时仍是直接换成大尺寸。
- 没有真机帧率与内存数据；按列错位绘制在 ESP32-C3 上的开销尚未测量。
